## 1. 已读源码与待核问题

`tools/prepare_hand_data.py:174–180` 将640×480原生坐标以整数floor缩到240×180，`events.npy`只存三个uint8列(x,y,p)。`tools/extract_subms.py:47–51` 用同一映射核对存储行，只补回微秒余数，不保存native pixel ID。`semkine/dataset.py:358–363` 训练时还逐缩放像素随机翻转极性；domrand会裁剪/删事件/注入hot pixel，GNN另有节点抽样。

M3的 `L_u(t_i)-L_u(0)+phase_u-C_u*s_i=0` 以**同一个物理像素的独立参考亮度状态**为条件。多个native pixels映到同一缩放格，不能因grid坐标相同就共用reference/C/s。原生完整流、经过丢弃的输入、图采样节点是三个不同信息合同；本审计不据此断定现有学习GNN失效。

一个无需真实标签的物理反例：两个原生像素当前对数亮度都为 `L(t)=v*t`，相同C，但合法初相分别0和C/3。它们的触发序列并集有交替的C/(3v)、2C/(3v)间隔；任何单个同亮度线性像素、任意固定正C'与单初相，在首次触发之后间隔必须恒定。因此空间合并一般不保持逐像素触阈模型，即使两处当前亮度完全相同；不能用一个“有效阈值”无条件修复。真实微秒量化/噪声另需建模，这个反例不声称真实每个格都不可拟合。

## 2. 冻结核查

仅顺序读取两个AEDAT4的event流到t>=1s后停止；允许解码最后一个覆盖边界的包，但只保存t<1s行。读取stream宽高元数据，要求640×480；不假定有已校准C/phase。沿原稳定ms分桶次序重排，逐行核对：

1. floor映射后的(x,y,p)与现有 `events.npy[:offsets[1000]]` 完全一致；
2. 原timestamp%1000与现有 `tsub.npy`对应前缀完全一致，offset counts逐ms一致；
3. 保存原timestamp/native x/y/p与对应存储行号到scratch NPY，文件hash绑定；不写任何data文件。

这些任一失败即INCOMPLETE，保留差异及停止，不修改转换/时间定义后重试。hash代码、两个输入前缀、offset/tsub前缀及输出身份；源AEDAT记录绝对路径/大小/mtime及参与核查的0≤t<1s事件数组hash，不涵盖已解码越界包其余行，不冒充全文件内容校验。

只在上述parity通过后统计：每个缩放格的native pixel数量、映入混合格的event数量、同格同极性相邻event跨native pixel的对数、同格全极性相邻event跨native pixel的对数。保留分母和空支持，不规定混合率收益门。统计仅说明所选整秒前缀的身份混合；混合格分母是该前缀有事件的格，整秒支持并集不是逐瞬间同时混合。微秒同时间戳按源存储次序打破并列，不证明亚微秒物理先后；同极性邻接跳过反极性触发，不能当作下一节的全部连续触发方程。不能推断全数据精度损失或所有邻接都是物质对应。

## 3. 对后续候选的限制

若prefix parity通过，证明在这两个前缀可从许可原始事件恢复native身份；不等于全数据sidecar已生成或新输入已经训练/通过原协议。保留native坐标/标定一致性是可能的必要接口修复，新增存储/处理费用须后续计入。不得把它直接采纳成新科学主贡献。

同一native pixel的相邻真实触发，在无漏报/无中间丢弃时可消去任意窗口初相：`L(t_i)-L(t_prev_event)=p_i*C_u`。这仍需正确历史pose/外观/C、极性与完整传感链；未知外观与过去误差不可隐藏，使用同一事件派生的亮度图不成为第二份独立测量。当前缩放格内邻接不满足此条件；GNN抽样后相邻节点也不保证是传感器相邻触发。
