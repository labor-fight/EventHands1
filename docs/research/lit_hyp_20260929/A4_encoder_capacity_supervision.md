## 1. 参数与 MACs 拆分

### 1.1 参数【代码事实】+【实验事实】

对 `configs/semkine/s37_routed_s3407.yaml` 实例化 `MNISTModel`，`sum(p.numel())` 与主行一致：

| 组 | 参数量 | 占比 | 出处 |
|---|---:|---:|---|
| **合计** | **733,830** | 100% | `outputs/semkine/s37_routed_main_row.json` `params_total`；本机复算同值 |
| frontend（`event_encoder`） | 445,952 | 60.8% | 主行 `params_frontend` |
| embed `Linear(7→128)` | 1,024 | 0.1% | `event_gnn.py:114` |
| EdgeConv×3 | 50,688 | 6.9% | `event_gnn.py:115`；`Linear(131→128)` ×3 |
| **embed+EdgeConv 主干** | **51,712** | **7.0%** | 与上下文「约 51.7K」一致 |
| **proj（mean‖max→512→512）** | **394,240** | **53.7%** | `event_gnn.py:120-124`；**只服务根头 feat** |
| `root_head` | 27,750 | 3.8% | `Linear(4624→6)`，`model/model.py:863` |
| `joint_heads`×15 | 253,485 | 34.5% | `model/model.py:868-871` |
| `prev_mlp` | 6,643 | 0.9% | `model/model.py:891-895` |

【代码事实】S37 `PREV_RENDER: false`，无 extra 通道；`readout=True`（非 mesh_query），故 `proj` 被构建且在 routed 路径喂给根头（`model/model.py:1471-1515`）。

### 1.2 MACs【实验事实】+【代码事实】

主行（`s37_routed_main_row.json`）：

- `macs_frontend` = 826,408,960（0.826 G）
- `macs_forward_packet` = 826,695,712（**0.827 G**）
- `macs_heads` = 286,752

本机 thop 复算 frontend = 826,408,960，与主行逐 bit 一致（`tools/make_s36_row.py:167-210` 口径；gather/topk/路由不计）。

解析拆分（饱和包 N=2048, k=8, L=3, H=128；`MAC = in×out` per Linear）：

| 块 | MACs | 占 frontend | 占 forward_packet |
|---|---:|---:|---:|
| embed | 1,835,008 | 0.22% | 0.22% |
| **EdgeConv×3** | **824,180,736** | **99.73%** | **99.70%** |
| proj | 393,216 | 0.05% | 0.05% |
| heads（公式同 `make_s36_row`） | 286,752 | — | 0.03% |

【代码事实】EdgeConv 每边 `Linear(H+3 → H)`，无下采样（`event_gnn.py:57-83, 220-222`）→ 算力 ∝ N·k·L·H²，与「51.7K 参数占 99.7% MACs」一致。

【推断】proj 占参数一半却几乎不算力：一次包级 mean‖max 后两层 MLP；EdgeConv 对 2048 节点×8 边×3 层重复同一小矩阵。

### 2.4 能否看到部件形状 / 50 ms 位移？【推断】（基于上表）

1. **空间**：global 三跳 bbox ≈ 整手尺度；边长中位 ≈ 一指段。节点特征在空间上**可以**覆盖「一只手轮廓量级」的邻域，**不是**只看单像素。
2. **时间**：三跳仅 **~2 ms（global）/ ~5–7 ms（local）**，远小于 50 ms 包长与手指位移时间尺度。【代码事实】`t_scale=1` 使「一包时间 = 一画面宽」（`event_gnn.py:108-109, 212-217`），稠密时归一化时间差极小，kNN 几乎退化为**近时刻的空间邻域**。
3. **结论倾向 M5 的时间半句**：部件**形状轮廓**有空间通道；**50 ms 内运动轨迹**进不了单节点的消息半径。窗口加长若仍用同一套因果窗+步长抽样，感受野时间上界几乎不变（与 §9.3 窗口 50→300 根旋转不变【实验事实】`00_CONTEXT.md` §4 相容）。

## 3. 梯度通路

### 3.1 计算图（结构）【代码事实】

```
events → token(全量) → sample → embed → EdgeConv×3 → h
                              ↘ mean‖max → proj → feat ──┐
h → route(a; no_grad) → pool e_j=[mean‖max‖cov] ─────────┤
                                                         ├→ root_head → Δt, ΔR
e_{k+1} ‖ θ_k^prev → joint_head_k → Δfinger_k
prev → prev_mlp → 加到 Δ
```

- 路由 `a`、距离 `d`、顶点 id 在 `no_grad` 中（`model/model.py:1388-1496`）；**d、v\* 不进损失**。
- 边摘要 `g` 在 routed 路径被 `_` 丢弃（`model/model.py:1471`）。
- 根读 `[feat ‖ e_0..e_15]`；手指 k 只读 `e_{k+1}`（`model/model.py:1155-1192`；契约 `tests/test_s37_routed_readout.py:170-186`）。

### 3.2 分损失梯度落点【实验事实】（CPU autograd，合成包）

| 损失切片 | 收到梯度的模块 | **不**收梯度 |
|---|---|---|
| 平移 `[:3]` | embed, EdgeConv, **proj**, root_head, prev_mlp | joint_heads |
| 根旋转 `[3:6]` | 同上 | joint_heads |
| 手指 `[6:51]` | embed, EdgeConv, **joint_heads**, prev_mlp | **proj**, root_head |

【代码事实】手指损失不经 `proj`：proj 只进 `feat`，而手指头不读 `feat`。

### 3.3 带外节点（>16 px）【代码事实】+【实验事实】

- 路由：`d > band_px` → `a=0`（`routed_readout.py:86-87`）。
- 证据池化：`a=0` 的节点不进任何 `e_j` 的加权均值/硬 max（`routed_readout.py:102-114`）。
- CPU 实测：根损失对 `h` 的证据路径上，OOB 节点 `grad≡0`，in-band 非零；同时 `feat`（经 proj 的全局 mean‖max）对根损失有梯度 → **OOB 节点只经 feat 收到根梯度**。

### 3.4 根读 e_1..e_15 与梯度竞争【代码事实】+【推断】

- 【代码事实】根对全部 16 行证据有梯度（测试钉死）。
- 【推断】完整加权损失下，分到手指关节的节点特征同时被 **根目标**（平移+旋转）与 **该指损失** 塑形；共享 EdgeConv 上两股信号叠加。手指无法经 proj 反哺，但根可经证据池「征用」手指邻域事件。这是共享主干上的结构性竞争，不是实现 bug。

### 4.3 对比 LNES + ResNet18【代码事实】+【实验事实】+【推断】

**LNES（`events.py:59-67`）**

- 保留：每 (像素, 极性) **最后一个**归一化时间戳；整窗空间布局。
- 丢失：同槽先前事件的时刻与次数、亚毫秒序（除非另开 count/first 面）。
- 文档宣称 50 ms 丢弃 **73.8%**（`events.py:65-66`，引自 `outputs/semkine/lnes_capacity.json`）。该 json **当前仓库不存在**。【待核】同文数字 23474→2367 算术上为 **89.9%** 覆盖丢弃，与 73.8% 不一致；PLAN 表写 74%（`.experiments/.../docs_PLAN_...` 摘录）。本机 zgz 重算（`lnes_recompute.json`）：global 覆盖丢弃 p50 **87.0%**，local **53.6%**；空槽率 global mean **95.7%**（文档 97.3% 同量级）。

**ResNet18（`model/model.py:878-889, 1545`）**

- 输入整幅 LNES（+可选渲染），`conv1` 适配后标准 ResNet18。
- 【推断】层级：早期层局部边、深层大感受野；末端全局池化 → **整窗空间感受野**，时间信息被压进两通道标量场而非显式轨迹。
- 【实验事实】同协议绝对 CNN `s37diag_cnnabs` RA 13.56 vs S37 20.74（`00_CONTEXT.md` §4）—— 更强整窗表示相关，但不单独证明「只有感受野」是差距源（表述/绝对 vs delta 等纠缠，M6）。

## 6. SAE 与抽样：丢弃事件带进多少信息？

【代码事实】`event_tokens` 在**全部事件**上算 SAE，再 `_sample`（`event_gnn.py:202-208`；`encoder.py:72-150, 153-171`）。

【实验事实】（对保留节点：全量 SAE vs 仅保留子集重算 SAE）

| | dense global | sparse local |
|---|---|---|
| SAE_same 因丢弃事件而改变的节点比例 p50 | **0.61** | **0.00** |
| 上一同极性事件落在被丢弃集合的比例 p50 | **0.77** | **0.00** |
| SAE_opp 改变比例 p50 | 0.09 | 0.00 |

【推断】

- **Dense**：SAE 把大量「未入图」事件的像素年龄压成 2 个标量带进节点——是弱的、无几何的旁路，**不是**把丢弃事件的 (x,y) 结构带回图。
- **Sparse**：几乎无丢弃 → SAE 旁路无增量。
- 对比 LNES：LNES 丢弃的是同槽历史；GNN 丢弃的是步长未选中的事件，但 SAE 部分回收了「该像素多久没同/反极性」。

## 8. 零训练可证伪检验（2–3 个）

1. **冻结 S37 特征上的绝对姿态线性探针**  
   固定 `event_encoder`(+路由池化)，在 TF 包上对 `feat`、`e`、`z=[feat‖e]` 做 ridge/线性读绝对 `R` / 手指。  
   - **否定 M5**：线性可解码误差 ≈ CNN 或显著 ≪ 当前根头 TF 误差 → 信息在特征里，头/融合才是瓶颈。  
   - **支持 M5**：与 §9.2 类似，绝对朝向 R²≈0 / 误差≈保持基线。  
   （§9.2 已对根旋转做过近亲版本；可扩展到「仅 h 节点、仅时间切片」消融。）

2. **打乱节点时间序 / 置换 t_norm 后特征不变性**  
   同一包打乱事件时间（保持 x,y,p）再编码，比较 `h`/`feat`/`e` 与闭环或 TF 指标代理（余弦、线性探针分数）。  
   - **若几乎不变**：模型本就没用时间结构 → M5 时间近视成立到「连已有 Δt 都没用」。  
   - **若崩溃**：时间通道有信息，瓶颈在跨度不够而非「完全无视时间」。

3. **因果窗 vs 对称窗（同参数、同抽样，只改邻域）的冻结特征探针**  
   不训练，仅前向：`window` 改为双向或扩大到 128/256，提特征做与 (1) 相同的绝对朝向探针。  
   - **探针无增益**：邻域时间跨度不是信息瓶颈（转向 M3/M6）。  
   - **探针明显增益**（而当前 32-窗无）：支持 M5，值得再开训练臂。
