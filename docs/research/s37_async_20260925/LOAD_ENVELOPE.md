全部 offsets 非递减、从零开始、非负，末 offset 不超过 events/tsub 长度；本次亦均等于 events 长度。events 均为 `(N,3) uint8`，tsub 均为 `(N,) uint16`，offsets 均为一维 `int64`；events 与 tsub 长度匹配，文件字节数符合 header。逐条 N、时长、shape/dtype 和 SHA256 见 JSON。**没有验证全部像素/极性内容、tsub 范围/顺序、实际微秒时间单调性或 GT 有效区间**。以下精确窗口计数按 offsets 所定义的毫秒 bin；把它解释成实际微秒事件区间，仍依赖未检查的 tsub 满足其 bin 约定。

## 1 ms append 包络

总计 2,079,784,201 个事件、4,634,632 个毫秒 bin（4,634.632 s），其中 789,260 个空 bin。对全部毫秒 bin 等权、NumPy linear quantile：P50 = 92，P95 = 2109，P99 = 3084，最大值 = 8321 个事件/ms。

现有 `max_events_per_append=8192` **不覆盖全部已观察训练负载**：两个 bin 超限，分别为 `lpc_global_v4` 的 `[50575,50576) ms`，8239 个；`ycy_global_v3` 的 `[14664,14665) ms`，8321 个。全局最大是容量的 1.0157470703125 倍。8192 是一次调用容量，不能解释成允许丢弃溢出事件；需要明确确定性分包并把所有子包、排队及输出计入计时，或重新冻结容量并验证成本。此清单既不规定实现改动，也不证明未知负载或验证/测试集受到同样上界约束。

## 2/4 ms query 与 2048 末节点读出

每条从 t=0 起按固定周期 `p∈{2,4} ms` 查询 `q=p,2p,...≤duration`，50 ms 历史窗 `[max(0,q−50),q)`，末 2048 个节点直接读出。原始末尾不足完整 query 周期的时段单独统计：2 ms/4 ms 分别合计 16/104 ms，本数据这些末尾均为零事件。未挑选 query 相位或片段。逐条比例完整保存在 `trials[i].queries["2"/"4"]`，包括冷启动查询和满 50 ms 窗口的单独口径。

记 `O[m]=offsets[m]`：窗内量 `Wq=O[q]−O[max(0,q−50)]`；截断命中为 `Wq>2048`，被省去的直接读出事件实例数为 `max(Wq−2048,0)`。同一事件可能出现于多次窗口，后者是事件×查询实例，不是唯一事件丢失率。

2 ms 共 2,317,308 次 query，1,912,162 次窗口超 2048（**82.51652348328319%**）；4 ms 共 1,158,632 次 query，956,062 次超限（**82.51645043465052%**）。窗口事件实例中分别 91.70315988119504% / 91.70311847183586% 不在该次直接读出节点集合。

另记相邻查询新事件数 `Aq=O[q]−O[q−p]`。由于 `p≤50 ms`，`max(Aq−2048,0)` 个较早的新事件在第一次可用查询时已被挤出末 2048，后续查询也不会恢复其直接读出身份。2 ms 此数为 357,820,470（全事件的 **17.204692190081697%**），4 ms 为 861,000,164（**41.39853373181769%**）；对应新事件量超 cap 的查询比例分别为 13.770288628011468% / 32.33994918144847%。这些事件仍可被前端编码并经图路径影响后继，**不等于前端输入丢弃，也不能从计数推出精度损失**；增量图能否保留有用信息及更改 cap 的精度代价必须另测。

## 冻结性能包络前的直接结论

不能以 8192 单包覆盖所有原训练 1 ms 负载，也不能把 2048 读出描述为全部历史事件被直接观察。正式计时需显式处理上述两个溢出 bin，并声明 query 相位、50 ms 历史与末 N 规则、初始化及持续运行方式；不可据本清单选择更低负载片段。本次没有测 latency，未证明 7 ms 达标，更没有证明任意负载的硬实时上限。
